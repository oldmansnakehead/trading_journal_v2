# Commit review plan

Scope: all 38 commits reachable from `b51bc16`, oldest to newest. Author is `bank`; Git metadata alone cannot identify which commits were generated by Antigravity. Review all commits in this range.

## Strategy

1. Inspect latest committed source to establish current risks and available checks.
2. Inspect every commit chronologically using its own requirements and ADR context. Apply current requirements separately as a final compliance check; do not retroactively fail old commits for features requested later.
3. Archive committed snapshots outside the working source under ignored `node_modules/.cache/commit-review`. Preserve uncommitted package/seed changes. No checkout/reset/stash.
4. Run node/web typechecks for runtime/config/dependency commits. Run unit tests where that historical commit defines a unit project. Inspect documentation-only changes without rerunning unchanged application checks.
5. Run latest snapshot bundle and lint. Run targeted regression reproductions for substantive findings.
6. Review findings with subagents as required by AGENTS.md, then verify evidence before accepting them.
7. Track introduced/fixed/still-present bugs separately; a later fix does not make the introducing commit pass.
8. Report per-commit results, limitations, and priority fixes. Do not edit implementation as part of this review.

- [ ] Check Electron isolation/sandbox, IPC input validation, navigation and image path containment where relevant.
- [ ] Check schema/migration pairing, foreign keys, image lifecycle, SQLite backup consistency and import rollback where relevant.

- [ ] Check Storybook stories and Vue Flow coverage for newly added pages/components.
- [ ] Execute applicable available automated checks; retain command output and exit codes.
- [ ] Distinguish code failure, tool/environment failure, unavailable coverage and skipped checks.
- [ ] Record severity, trigger, consequence, commit/file/line evidence and subsequent resolution.

## Test isolation and interpretation

- Existing E2E tests launch `electron.launch({ args: ['.'] })` without a dedicated `userData` path; the fill-trade test creates records. Do not execute them against personal data.
- E2E completion requires a dedicated temporary data directory, updater/network disabled during tests, deterministic fixtures, current selectors, screenshots, and PDF report verification. This is pending, not passed.
- This first historical sweep reuses installed dependencies for speed. Its results are compatibility diagnostics, not exact lockfile-reproducible historical builds. Dependency-related failures require a subsequent exact-version install before attribution to a commit.
- Production packaging, native module loading, backup/import recovery, Storybook browser interactions and visual behavior require additional isolated runtime checks; typechecks/unit tests/bundling alone cannot certify them.
- Automated test success does not certify formula correctness or requirements completeness.
